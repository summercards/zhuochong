# assets/ —— 游戏资产目录规范

> 本目录是**运行时资产的唯一入口**。引擎只从这里加载东西；
> 一切 Blender 源文件、审计日志、中间产物都留在 `角色资产/` 与源工程目录里，不进这里。

---

## 一、三桶定义（模型 / 蒙皮 / 动画）

这是本项目对「模型 + 蒙皮 + 动画文件归类」的硬约定。三桶**按内容物**划分，不按用途。

| 桶 | 目录 | **必须包含** | **必须不含** | 典型用途 |
|---|---|---|---|---|
| **模型 Model** | `characters/<id>/model/` | 网格、UV、法线、材质槽 | ❌ 骨架 ❌ 蒙皮 ❌ 动画 | 碰撞体生成、剪影对照、LOD 基准、道具静态引用 |
| **蒙皮 Skin** | `characters/<id>/skin/` | 网格、材质、**骨架**、**顶点权重** | ❌ 动画 | 换装基准、绑定校验、无动画的静态摆拍 |
| **动画 Animations** | `characters/<id>/animations/` | 网格、材质、骨架、顶点权重、**N 段 clip** | — | **游戏运行时主角/敌人** |

**为什么要有 model 桶？** 蒙皮文件里网格的静置坐标是"被骨架摆过"的，做碰撞盒或量剪影时不可靠。
model 桶给的是**未蒙皮的原始几何**，尺寸即真实尺寸。

**为什么要有 skin 桶？** 它是"骨架 + 绑定"的干净副本。换装、加挂点、验权重时用它，
不会被 68 段动画拖慢、也不会误改到动画。

## 二、目录树

```
assets/
├── characters/                ← 角色（每个角色一个 id 目录）
│   └── <char_id>/
│       ├── model/             模型桶
│       ├── skin/              蒙皮桶
│       ├── animations/        动画桶（含 manifest.json）
│       ├── textures/          贴图
│       └── README.md          角色资产卡（尺寸、骨骼、轴向、动画清单索引）
├── vfx/                       ← 特效（粒子 / 网格特效 / 贴花）
├── ui/                        ← 界面（血条、字体框、图标）
├── fonts/                     ← 字体
└── shared/                    ← 跨角色通用：公共材质、碰撞代理、公共着色器
```

## 三、命名规范

```
<char_id>_<role>_v<NNN>.glb
   │        │      └── 三位版本号，从 001 起
   │        └───────── model | skin | anim
   └────────────────── 小写下划线，与目录名一致
```

示例：`bigman_model_v001.glb` / `bigman_skin_v001.glb` / `bigman_anim_v001.glb`

- 文件名**全小写**、下划线分隔（Godot 导入后不区分大小写，混用会撞名）。
- 版本号**只增不改**。要改内容就出 `_v002`，不要覆盖 `_v001`。
- 元数据一律写进 `animations/manifest.json`，**不要**在文件名里塞参数。

---

## 四、硬规则

1. **引擎目录零脚本、零日志、零 `.blend`。** 出现即视为污染。
2. **不留 `.blend1`、`.import` 手工文件。** 由 Godot 自动生成。
3. **同一角色的三桶必须同版本。** `model v001` 配 `skin v001` 配 `anim v001`；
   三者的三角面数必须一致，不一致说明几何被改过（用 `tools/verify_assets.py` 卡）。
4. **贴图缺失是有意为之时，必须留 `textures/README.md` 说明。** 静默 0 张贴图会被误判为漏导出。
5. **遗产/废弃资产不进本目录。** 见 `docs/资产归类.md` 的 legacy 章节。
